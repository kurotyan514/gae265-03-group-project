# 好險有你 — UI 設計稿（給 AI 前端實作用）

> 版本：v1.8（由原型 HTML 反向整理）
> 搭配檔案：`design-tokens.json`（唯一真實來源）、`tokens.css`、`tailwind.preset.js`、`assets/`
> 單位：邏輯 px；斷點：桌機 ≥768px，行動 ≤767px（desktop-first）

---

## 0. 給 AI 的實作規則（請先讀）

1. **只用 token。** 顏色、字級、圓角、陰影、間距都從 `tokens.css` 的 CSS 變數或 `tailwind.preset.js` 取。不要自己發明新色碼、新字級或新陰影。
2. **按鈕一律白底。** 主要按鈕不是實心綠色，而是白底加 2px 品牌色框線。這是本產品刻意的視覺決定，請勿改成實心填色按鈕。
3. **只用兩種字重**：400 與 700。
4. **一頁只有一個主要動作**，放在動作列最右邊（`margin-left: auto`）。返回類按鈕放左邊。
5. **語言是繁體中文（台灣）**，文案語氣見第 10 節。數字用千分位逗號，金額寫「元」或「萬」。
6. **右下角的「示範導覽」按鈕與面板不是產品功能**，正式實作時不要做。
7. 方案、金額、保費、條款代碼都是示意資料。資料結構見第 11 節。
8. 標記為 **proposal** 的 token（目前只有 `--color-accent-text`）是為了修正對比度而新增，實作時請優先使用；若要完全還原原型外觀，改用 `--color-accent`。

## 1. 產品概要

| 項目 | 內容 |
|---|---|
| 產品名 | 好險有你 |
| 副標（頁首 tagline） | 旅遊保險推薦與理賠陪伴 |
| 登入頁標語 | 出發前幫你選方案，出事時幫你處理理賠。 |
| 目標使用者 | 單人、出國旅遊、15～80 歲 |
| 登入方式 | Google 帳號 |
| 吉祥物 | 寄居蟹（`assets/crab.png`） |

**兩條主要功能：**

- **功能一「出發前：幫我選方案」**：輸入旅遊背景 → 選在意的點 → 看推薦方案與比較表 → 情境試算與 AI 問答。
- **功能二「出事了：幫我處理理賠」**：建立行程（上傳或手動選保單）→ 用對話描述事故 → 看狀況總結與理賠待辦 → 上傳文件 → 用使用者自己的 Gmail 寄給保險公司。

## 2. 設計原則

| 原則 | 在畫面上的做法 |
|---|---|
| 安心、不施壓 | 米白底、深綠字、白色卡片、柔和陰影；不用大面積飽和色 |
| 一眼看懂重點 | 每頁只有一個主要動作；推薦一律用 3px 品牌色框標示 |
| 狀態用顏色點，不用色塊 | 綠點＝可能適用／完成，珊瑚點＝不在範圍／需處理，黃點＝待確認 |
| 重點用黃色「筆觸」 | 情境故事左線、重大注意事項左線、分組標題前短條、★、Logo 筆觸 |
| 誠實標示不確定 | 每個試算與 AI 回答都附「依據」與免責文字 |
| 白話 | 先講結論再講條件；保險術語可點開名詞解釋 |

### 6.8 在意點卡 ConcernCard `.ccard`

- 容器：grid `repeat(auto-fill, minmax(200px, 1fr))`、間距 16（行動固定兩欄、間距 12）。

- **已選滿 3 項時**：未選的卡 disabled（opacity .4）。

### 6.9 分段選擇器 SegmentedControl `.seg`

- 外框 1px border、圓角 12、白底，自身寬度（`align-self: flex-start`）。

- 選中段：surface-soft 底、heading 字、inset 2px brand 框、圓角 11。

### 6.10 檔案拖放區 FileDrop `.drop`

- 2px 虛線 border、圓角 16、bg 底、內距 22/24、內部垂直間距 10。

  4. 免責「僅供比較參考，非投保建議。保費以保險公司官網試算為準。」
  5. 動作列（`.m2`）：上一步／**情境試算與問答**（主要）／完成
- 使用者改保額：價格與比較表金額即時更新，卡片標籤改為「保額（已自行調整）」並顯示原推薦保額。
- 「前往保險公司官網投保 ↗」：新分頁開保險公司投保頁。
- 點保障項目名稱 → 名詞解釋對話框（說明＋兩個方案各自的條款依據）。
- **沒有符合方案時**：標題「沒有符合條件的方案」，說明「請調整年齡、目的地或日期後再試一次。」，只有「上一步」。

### 7.7 1-4 情境試算與問答

- 寬版。麵包屑「出發前：幫我選方案」，說明「選一個情境看看各方案賠多少，也可以直接問問題。」
- **情境試算卡**：分頁（5 個情境）→ 故事＋假設 → 試算卡。

  | 情境 | 涵蓋的在意點 |
  |---|---|
  | 航班延誤 | 班機延誤、行李延誤 |
  | 生病住院 | 突然生病就醫 |
  | 行前取消 | 行程取消或更改 |
  | 錢包被偷 | 行李遺失或損壞、證件遺失、信用卡盜刷 |
  | 騎車撞傷 | 緊急送醫、弄傷別人 |

  涵蓋使用者在意點的情境加 ★ 並排前面（依該在意點的排序），其餘依上表順序。
- **問答卡**：H2「問答」→ 對話區（空時顯示「點下方常見問題，或自己輸入。問答內容不會保存，離開這頁就會清空。」＋常見問題 Chip）→ 提問列（300 字）→ 免責。
- 常見問題 Chip：兩個方案差在哪？（只有一個方案時不顯示）／班機延誤多久才能賠？／行李遺失怎麼賠？／在國外看病要先自己付錢嗎？
- 動作列：回比較表／完成（推到右）。

### 7.8 2-1 建立行程

- 窄版。麵包屑「出事了：幫我處理理賠」，說明「填好這趟旅行的保單，之後的判斷與待辦都依這張保單產生。」
- 卡片表單：
  1. 分段選擇器：上傳保單／手動選擇
  2. 上傳模式：拖放區（「PDF、JPG、PNG，10 MB 內。個資會先移除再讀取，原檔不保存。」）
     手動模式：若有過去的比較，顯示「從過去的比較帶入」按鈕 → 底部抽屜選比較 → 再選推薦或次推薦
  3. 保險公司｜方案（雙欄，方案依公司連動，未選公司時 disabled「先選保險公司」）
  4. 保額｜目的地（雙欄，保額依方案連動）
  5. 保險期間：開始日｜結束日
- 自動帶入的欄位下方顯示「✓ 由保單自動帶入，可修改」；讀不到的顯示「保單上讀不到，請自行選擇」。
- 從比較帶入後顯示警示「已帶入之前比較的資料，請依實際購買的保單確認方案、保額及保險期間。」
- 動作：上一步（回首頁或回 2-2）；下一步（全填且結束日不早於開始日）→ 存檔 → 2-2，Toast「已存檔」。

### 7.9 2-2 描述事故

- 窄版。麵包屑「出事了：幫我處理理賠 · 描述事故」，標題「日本 2026/07/05～07/10」，說明「富邦產險 B 方案 · 400 萬」。
- 一張卡：對話區（最小高 320）→ AI 追問的選項 Chip → 提問列（500 字，placeholder 依狀態「回答上面的問題，或點選項」／「描述發生的事」）。
- AI 第一句固定為「發生什麼事了？用一兩句話描述就好，例如：颱風來了，回台灣的班機被取消。」（「有新狀況」時改為「發生了什麼新狀況，或哪裡需要修正？」）
- AI 依事故類型逐題追問（日期、地點、各類型欄位），使用者可打字或點 Chip。描述完成 → 2-3。
- 動作：上一步（回 2-1 修改保單）／回首頁。

### 7.10 2-3 行程頁

- 窄版。由上而下：
  1. 麵包屑
  2. 行程狀態列（6.22）
  3. H2「狀況總結」＋事故卡（依日期排序）＋免責
  4. 重大注意事項（有才顯示）

  6. 送件區（有需上傳的待辦才顯示）
  7. 問答卡（已結案時改為「此行程已結案，只能查看與下載文件。」）
  8. 動作列：完成
- **有新狀況**：在問答區開啟草稿對話（Pill「新狀況對話中（草稿）」＋「取消」），完成後重新產生總結與待辦，新增的待辦加「新增」Tag。取消 → Toast「已取消，原總結與待辦不變。」

- 待辦內上傳 → 首次需授權 Google Drive 對話框。
- 沒有待辦的說明：
  - 有待確認事項：「目前沒有待辦：有項目在待確認事項，用「有新狀況」補充資訊後會產生待辦。」
  - 沒有可能適用項目：「目前沒有「可能適用」的保障項目，所以沒有待辦。」

### 7.11 2-4 上傳理賠文件

- 窄版。說明「日本 2026/07/05～07/10 · 富邦產險 B 方案」。
- 由上而下：
  1. 「還缺的文件」待辦卡（Pill「N 份」，依事故分組，只列名稱與空白方框）；全齊時「需上傳的文件都已備齊。」
  2. 拖放區：說明「可一次選多份，手機可直接拍照；PDF、JPG、PNG，每份 10 MB 內。上傳後依「事故類型_待辦名稱_序號」重新命名，存在你自己的 Google Drive。」；未授權時按鈕為「授權 Google Drive 後上傳」
  3. 辨識結果卡（上傳後才出現）：每份檔案一列，結果為通過／不符合規定／不是需要的文件／無法辨識（需手動選對應待辦）
  4. 還缺文件時的說明＋「看提醒信範本」連結
  5. 動作列：回行程頁／**去送件**（全齊）或 **稍後再傳**（未齊，Toast 提示提醒信規則）

### 7.12 2-5 送件

三種狀態：

1. **文件未齊**：卡片「需上傳的文件還沒備齊，備齊後才能送件。」＋回行程頁／上傳文件。
2. **詢問**：卡片 H2「要由我們用你的 Gmail 幫你寄給保險公司嗎？」＋說明「寄件者是你自己的 Gmail；Gmail 權限只用來寄這封信。兩個選項都會讓行程結案。」＋「我自己處理就好」／「好險有你小助理幫我送出」（主要）。選後者首次要 Gmail 授權對話框。
3. **確認信件**：標題「確認信件」、說明「內文可修改，「（請填寫）」都填好才可寄出。」
   - 信件預覽：收件者（保險公司理賠信箱）、寄件者（使用者 Gmail）、主旨（可改）、內文（可改）、提示列（有未齊文件時）、附件清單。
   - 錯誤列：「還有 N 處「（請填寫）」要填（保單號碼、被保險人姓名、聯絡電話）。」
   - 動作：取消／寄出（填完才啟用）→ 確認對話框「確定寄出？選擇後此行程即結案，之後無法再新增狀況或修改。」→ 回 2-3。

## 8. 互動與狀態規則

| 規則 | 內容 |
|---|---|
| 自動存檔 | 比較與行程每次操作都更新「最後操作時間」，首頁依此排序 |
| 字數上限 | 其他在意的事 200、問答 300、描述事故 500；計數即時更新 |
| 檔案 | PDF／JPG／PNG、每份 10 MB 內、可多選 |
| 檔名 | 上傳後改為「事故類型_待辦名稱_序號」 |
| 待辦完成 | 多數文件上傳一份即完成；部分文件可用替代組合（例：機票＋登機證，或搭機證明） |
| 刪除檔案 | 若刪除後不再完整，待辦回到未完成 |
| 可送件 | 所有需上傳的待辦都不是未完成，且至少有一份檔案 |
| 提醒信 | 缺文件滿 24 小時寄第一封，之後每 3 天一封，最多 3 封；新增需上傳待辦時重新計時；備齊或結案即停止 |
| 結案 | 自行處理或寄出後，行程唯讀（不可新增狀況、勾選、上傳、刪除） |
| 問答保存 | 功能一的問答離開頁面即清空；功能二的問答保存在行程內 |
| 外部連結 | 投保頁、理賠申請書、Gmail 對話串都以新分頁開啟 |
| 動態效果 | hover 150ms、展開箭頭 200ms；`prefers-reduced-motion` 時全部關閉 |

## 9. 無障礙

- 所有可點的卡片、列、Logo 都是 `<button>`，不是 `<div>`。
- focus-visible：3px accent 外框、offset 2（輸入框改用品牌色框＋光暈）。
- 狀態訊息用 `role="status"` 或 `aria-live="polite"`；錯誤用 `role="alert"`。
- 切換類元件用 `aria-pressed`／`aria-selected`／`aria-expanded`。
- 純裝飾 SVG 加 `aria-hidden="true"`；只有顏色意義的點要給 `aria-label`。
- 表格用正確的 `th scope`；比較表用 `role="table"` 系列。
- **對比度注意**（WCAG AA 一般文字需 4.5:1）：

  | 組合 | 對比 | 結論 |
  |---|---|---|
  | accent `#78a817` 字／白底 | 2.83 | 不足，綠色文字改用 `accent-text #55790f`（5.09） |
  | 白字／accent 圓鈕 | 2.83 | 只放圖示可接受（非文字），但建議圖示加粗 |
  | 白字／alert 徽章 `#ff654b` | 2.91 | 不足；可接受做法是徽章數字加大加粗，或把底色加深 |
  | muted `#647364`／白底 | 5.03 | 通過 |
  | brand `#285442`／白底 | 8.62 | 通過 |

## 10. 文案

### 語氣

- 用「你」，白話、短句、先講結論。
- 不保證理賠，一律寫「可能適用」「實際以保險公司審核為準」。
- 數字：千分位逗號；金額「6,000 元」、保額「400 萬」；日期「2026/07/05」，同年區間寫「2026/07/05～07/10」。
- 中英文、數字與中文之間加半形空格（例：「每滿 4 小時」）。

### 固定文案

| 位置 | 文案 |
|---|---|
| 1-3 小註 | 示意資料，非實際報價 |
| 1-3 免責 | 僅供比較參考，非投保建議。保費以保險公司官網試算為準。 |
| 試算卡 | 僅為依情境假設的試算，實際以保險公司審核為準。 |
| AI 問答 | 回答由 AI 依條款整理，實際以保險公司審核為準。 |
| 狀況總結 | 以上為可能適用的項目，實際以保險公司審核為準。 |
| 全部完成 | 目前列出的待辦已完成，請依保險公司指示確認後續處理。 |
| 載入 | 正在比較方案… |

## 11. 資料模型摘要（前端狀態）

```ts
type Tier = 'high' | 'mid' | 'low';           // 目的地費率等級
type Item = 'death'|'injmed'|'illmed'|'fdelay'|'cancel'|'shorten'
          |'bdelay'|'bloss'|'doc'|'card'|'rescue'|'liab';

interface Plan {                    // 保險方案
  co: string; n: string;            // 公司代碼、方案名
  age: [number, number]; days: number; dest: string[];
  sums: number[];                   // 可選保額（萬）
  per: number; ill: number;         // 費率、疾病醫療比例
  v: Partial<Record<Item, number | { u?: number; h?: number; a: number; max?: number }>>;
}

interface Comparison {              // 功能一：一次比較
  id: string; dest: string; dep: string; ret: string; age: number;
  concerns: string[];               // 在意點 id，依順序，最多 3
  note: string;                     // ≤200 字
  progress: 'bg' | 'rec';
  result?: { rec: string; alt?: string; sums: Record<string, number>;
             days: number; reason: string; basis: string[]; sumNote: string; none?: boolean };
  adj?: Record<string, number>;     // 使用者調整的保額
  last: number;                     // 最後操作時間
}

interface Trip {                    // 功能二：一個行程
  id: string; plan: string; sum: number; dest: string; start: string; end: string;
  progress: 'desc' | 'sum';         // 描述中／已產生總結
  incidents: Incident[];
  todos: Todo[];
  send: { st: 'none' | 'self' | 'sent'; at?: string };
  qa: unknown[]; last: number;
}

interface Incident {
  id: string;
  type: 'fd'|'fc'|'bd'|'bl'|'md'|'dl'|'cc'|'tc';  // 班機延誤、班機取消、行李延誤、
                                                  // 行李遺失、就醫、證件遺失、盜刷、旅程取消
  ans: Record<string, string>;      // 追問欄位的回答
}

interface Todo {
  iid: string;                      // 所屬事故 id，或 'trip'（整個行程）
  code: string;                     // 文件代碼 D01…D23
  st: 'todo' | 'done' | 'na';
  files: string[]; isNew?: boolean;
}
```

文件定義（DOCS）每筆有：名稱、時機（`now` 事故當下／`home` 回國後）、注意事項、是否需上傳、等待時間、是否為申請書、可替代組合。

## 12. 原型中建議統一的地方

實作時可順手修正，不影響外觀：

1. **散落的寫死色碼**：`#c23a22`、`#9a6a00`、`#fff6dd`、`#fff0ed`、`#a2321f`、`#fff8e3`、`#7a5600` 都已收進 token，請一律改用變數。
2. **圓角種類偏多**：原型出現 10／11／12／14／16／18／20／22／24／26。已收斂成 sm／md／lg／xl／2xl／card／full；20、22、26 都是膠囊，用 `full`。
3. **綠色文字對比不足**：見第 9 節。
4. **內容待補**：「突然生病就醫」「需要緊急送醫或家屬趕來」「不小心弄傷別人或弄壞東西」三個在意點的故事與假設仍是「待補」；除富邦、國泰外的 7 家公司名稱為示意。
5. **示範導覽面板**：僅供原型試用，正式產品不實作（其中 13px 字級也不納入 token）。
