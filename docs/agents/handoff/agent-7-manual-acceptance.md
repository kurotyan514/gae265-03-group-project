# 7 號手動驗收：真的 Google 登入、Drive、Gmail（#155、#74）

> 狀態：**步驟已整理，還沒有人實際走過**。CI 與自動測試都不連 Google（ADR-0020），這份要由 7 號開發者用自己的測試帳號手動走。
> 走完把每一步的結果（截圖或描述）貼到 [#155](https://github.com/kurotyan514/gae265-03-group-project/issues/155)（#74 的部分貼到 [#74](https://github.com/kurotyan514/gae265-03-group-project/issues/74)），發現的問題各開一張票並標明歸屬（平台／6 號／7 號）。
> 通用的登入與授權檢查在 [google-login.md](google-login.md)「驗證清單」；這份只寫 7 號送件相關的部分。

## 安全規則（先看）

- **收件者只用自己的測試信箱**，不要寄到任何真實保險公司或業務員的信箱。建議收件者用測試帳號自己的信箱或 `+` 別名（例如 `you+claims@gmail.com`）。
- `GOOGLE_CLIENT_SECRET`、`TOKEN_ENCRYPTION_KEY`、token 只放 `.env`，**不貼到 issue、截圖、commit 或對話**。截圖前把網址列的 `code=`、`state=` 遮掉。
- 上傳的文件用 `backend/app/agents/document/samples/` 的虛構範例（`delay.pdf`、`boarding_pass.pdf`、`claim_form.pdf`），不要用真的證件或機票。
- 空格（被保險人姓名、保單號碼、聯絡電話）填虛構的值，例如「測試王」「TEST-0001」「0900000000」。

## 事前準備

1. Google Cloud 的 OAuth 用戶端已設定，測試帳號已加進「測試使用者」名單（見 `docs/agents/dev-environment.md`）。
   - 授權重新導向 URI 要有 `${PUBLIC_BASE_URL}/api/v1/auth/google/callback`（本機是 `http://localhost:5173/api/v1/auth/google/callback`）。
   - OAuth 同意畫面要列出 `drive.file` 與 `gmail.compose` 兩個 scope。#74 要確認的「`drive.file` 需不需要 Google 審核」：在 Cloud Console「OAuth 同意畫面 → 資料存取權」看 Google 把兩個 scope 歸在哪一類（非機密／機密／受限），把畫面上的分類記到 #74。測試模式下只有測試使用者能授權，不影響這次驗收。
2. `.env`：
   ```
   GOOGLE_CLIENT_ID=<你的>
   GOOGLE_CLIENT_SECRET=<你的>
   TOKEN_ENCRYPTION_KEY=<產生一次，之後不要換>
   PUBLIC_BASE_URL=http://localhost:5173
   AGENT_5_IMPL=v1
   AGENT_6_IMPL=document
   AGENT_7_IMPL=gmail
   DOCUMENT_DEV_FAKE_STORAGE=false
   ```
   `DOCUMENT_DEV_FAKE_STORAGE` 一定要是 `false`：假存檔的 `storage_path` 不是 Drive 的檔案編號，7 號取檔會失敗。
3. `make up`（改了 `.env` 要重啟後端）→ `make seed` → `make doctor` 全部 PASS。
