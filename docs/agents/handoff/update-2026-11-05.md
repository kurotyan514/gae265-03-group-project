## 2. 現在你要做什麼

### 第一步（每個人都要）：更新程式碼

PR #81 合併進 `main` 之後：

```bash
git switch main
git pull --ff-only
git switch 你自己的分支
git merge main
```

如果出現「衝突（conflict）」，**先停下來**，把畫面貼給你的 AI 助手，或問平台負責人。不要自己亂選一邊。

接著重新載入資料並檢查環境：

```bash
make doctor     # 檢查環境，要全部 PASS
make seed       # 重新載入條文、事件類型和待辦範本（重跑是安全的）
```

`make doctor` 有 FAIL 的話，畫面會告訴你怎麼修，通常是忘了 `make up`。

### 第二步：跑測試，確認你的實作沒壞

```bash
CONTRACT_AGENT_5=你的註冊名稱 make test args="-k contracts"
```

（6 號用 `CONTRACT_AGENT_6=...`，7 號用 `CONTRACT_AGENT_7=...`。還沒有真實實作的人，直接 `make test args="-k contracts"` 跑假的就好。）

### 懶人做法：貼給 AI 執行

上面的更新與測試，可以直接請你的 AI 助手代勞。選你的號碼，整段貼到 AI 對話裡。AI 會先確認平台的 PR 已合併，遇到衝突或失敗會停下來問你。

### 5 號要注意

- 事件類型代號請用真實資料的：`flight_delay`、`flight_cancel`、`baggage_delay`、`baggage_loss`、`medical`、`document_loss`、`card_fraud`、`trip_cancel`。還沒判斷出來時是 `other`。
- 流程是：先追問（問必問欄位），問完才回報 `incident_type_code`，這時平台才會產生該類型的待辦。
- 目前契約測試的「整條流程」是照**假的 5 號**寫的：使用者說兩句話就問完。真實的 5 號會問更多題，這個測試可能會失敗。**這是測試太簡單，不是你的程式有錯。** 遇到時請告訴平台負責人，我們會在契約 v2 的測試裡一起改（見下一節的 B4）。不要自己改契約檔。

### 6 號要注意

- 班機延誤現在有**更多項需要上傳**的待辦，你的文件辨識會被呼叫更多次。
- 目前待辦還沒有文件代碼（`D01`、`D02`…），你只能靠待辦的標題去對。標題以後可能會改，這個問題 contract v2 會解決（B3），先照舊就好。
- 現在一項待辦只能放一份文件，重傳會取代舊的。要改成可以放多份是 B1，還沒做。
- 「存摺封面與護照影本」要不要保留、文件規則怎麼維護，已經交給 6 號處理。你決定之後告訴平台負責人，我們會改資料檔。

### 7 號要注意

- 這次沒有改到你的契約和資料。
- 要先知道：Google 授權之後會要求一次同意 **Gmail 和 Drive（`drive.file`）** 兩種權限。客人只授權一次，6 號和 7 號共用。動手做授權之前，先跟平台負責人確認。

### 做法三：遇到不確定的事，怎麼問

好的問法包含四件事，貼給平台負責人最快得到答案：

1. 我是幾號。
2. 我執行了什麼指令。
3. 畫面出現什麼（整段貼上，不要截一半）。
4. 我已經試過什麼。

## 名詞小字典

- **契約**：兩邊事先約好的資料格式。平台給你什麼、你要還給平台什麼，寫在契約檔裡。
- **契約測試**：自動檢查你的程式有沒有照契約做的測試，名稱含 `contracts`。
- **假實作（fake）**：平台寫的替身，用來示範輸出長什麼樣子，也讓還沒完成的人可以先跑流程。
- **seed**：把條文、事件類型、待辦範本放進資料庫的資料。`make seed` 就是載入它。
- **待辦（todo）**：使用者出事後要完成的事，例如「取得診斷書」。
- **分支（branch）**：你自己的工作副本，改壞了不會影響別人。
- **合併（merge）**：把別人的更新放進你的分支。
- **衝突（conflict）**：兩個人改了同一個地方，電腦不知道要留哪個，需要人決定。
- **PR**：請大家檢查你的改動、同意後放進主線的申請。
- **migration**：資料庫結構變更的記錄檔。
