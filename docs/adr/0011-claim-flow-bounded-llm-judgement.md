# 事件釐清與待辦清單：流程由程式決定，LLM 的情境判斷只在有界範圍內

事故發生後的事件釐清與待辦清單，延續 [ADR-0004](0004-llm-never-produces-numbers.md) 規則 2：要問什麼、問幾次、何時結束都由程式決定，LLM 只負責聽懂與說人話。唯一的有界例外是：LLM 可以依情境提議最多 2 題追問。這是對 ADR-0004 規則 2 的刻意鬆綁，不是漏掉。

## 事件釐清

- 事故類型固定：醫療或意外傷害、行李遺失或被竊、班機延誤或取消、旅程取消或縮短、第三人責任、其他。
- 每種類型有固定的必問欄位（發生時間、地點、經過、是否就醫、是否報警等）。LLM 把使用者的話抽成欄位片段，由程式合併（`None` 不蓋掉已知值，無效值忽略並記錄，同 ADR-0004 規則 3）。
- 程式決定下一個要問哪個欄位；必問欄位都有了或使用者選擇略過就結束，並設最多輪數。
- 必問欄位之外，LLM 可依情境提議最多 2 題追問（例如行李被竊時加問「是否已向警方報案」）。次數上限與結束仍由程式控制，答案存成自由文字 `extra_notes`，不進結構化欄位。
- 結束時才建立**理賠案件**；對話本身可以沒有案件。

## 待辦清單

- **基本款**由程式讀資料檔（暫定 `backend/data/config/claim_checklist.json`），依事故類型決定，不由 LLM 產生。
- **擴充項目**可由 LLM 依保單內容與 `extra_notes` 提議，但每一項必須附出處（保單或條文的頁碼、條號），程式驗證該出處真的存在於檢索到的原文。沒有可驗證出處的項目不加入，改成提醒「請向保險公司確認」。
- 每個項目的出處與勾選狀態存在資料庫，給後續的文件辨識（流程圖的 6）去勾。

## Considered Options

- **完全由程式問答**：最可預測，但事故情境差異大，固定欄位問不到像「是否報案」這類只在某些情境才需要的事。
- **讓 LLM 自由決定流程**：彈性最高，但問什麼、何時結束都無法測試與重現，違反 ADR-0004。
- **程式為主、LLM 有界追問**（採用）：保留可測性，追問上限讓偏差有限。

## Consequences

- 驗收：基本款 100% 出現；擴充項目 100% 有可驗證出處。
- `extra_notes` 是自由文字，可能含個資，需要走 [ADR-0009](0009-policy-document-personal-data.md) 的規則與刪除連動。
