# 官網方案只供保單比對，不進手選與推薦

富邦官網賣的「國外旅平險_C方案_加購」跟易安網的九個方案是不同商品。旅客上傳這種保單時，現有的比對（[ADR-0013](0013-policy-upload-matches-catalog-plans.md)）會把它判成「富邦進階型＋加購一項」，保單上的商品名稱與方案名稱對不上，旅客看不出系統有沒有讀對。但官網商品沒有保費與保障明細（易安網試算表裡沒有它），價格與額度又不能編造（[ADR-0004](0004-llm-never-produces-numbers.md)）。

## 決定

- `config/plans.json` 的方案可以標 `upload_only`，稱為**保單專用方案**：只能由保單上傳比對到。
- 保單專用方案不出現在方案清單（`GET /plans`）、不能手選建立保單、不能選來建立對話；推薦本來就只看有保費資料的方案，不受影響。
- 比對規則不變：方案的保單代碼全部出現在保單上才算，多個方案符合時取代碼最多的。官網 C 方案（加購）有 20 個代碼，比進階型多一個，所以含這一章的保單會比對到它；只有進階型 19 個代碼的保單仍比對到進階型。
- 方案名稱不含版本號（保單上的「115.04版」），日後官網改版不用改方案。
- 沒有保費與保障明細就不編；投保連結留空，因為它不會出現在推薦卡片上。

## 考慮過的做法

- **不新增方案，維持進階型加購**：資料與條款完全相同，只差方案名稱。但旅客看不到自己買的是官網 C 方案，之後也沒有地方放這個商品自己的設定。
- **新增只含 19 個代碼的 C 方案**：代碼數與進階型一樣，比對會平手，結果取決於設定順序，不穩定。
- **補假的保費資料讓它能手選**：違反 ADR-0004。

## 後果

- 方案現在有兩種：可選方案（九個）與保單專用方案。新增官網商品時，若沒有保費資料就照這份做；有保費資料時才當一般方案。
- 讀取方案的地方要分清楚「所有方案」（保單比對、查方案名稱）與「可選方案」（清單、手選、對話）。
- 官網 C 方案（不含加購）是否另有對應，PDF 看不出來，這次不處理。
