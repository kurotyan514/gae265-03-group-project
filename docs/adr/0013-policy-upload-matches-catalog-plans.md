# 上傳保單只和條款庫比對方案；比對到才建立保單，問答一律用條款庫的條文

使用者上傳保單 PDF 的用途只有一個：確認他買的是條款庫裡有的商品方案。程式從保單文字抽出險種代碼（`T\d{3}`、`TA\d{2}`）或險種全名，與條款庫**完全比對**；某個方案（`app/domain/plans.py`）的險種**全部**比對到，才算比對到這個方案。比對不到就回 422，不建立任何資料。比對由程式做，LLM 不參與，也不做模糊比對。

比對到之後：

- 建立 `policy`（屬於使用者，記 `plan_id`、身故及失能保額 `sum_insured`、保障起迄日 `start_date`／`end_date`）。保單上方案以外加購的保障記在 `policy_addon`（對應 HTML schema 的 `policy_addons`；因為條款庫的險種是合訂本裡的一份條款，加購常只是其中一章，所以多一個可為空的 `section` 章名欄位）。方案含哪些險種不另存，由方案設定決定。
- 使用者選這份保單發問（`POST /policies/{id}/conversations`），建立 `conversation`（綁 `policy_id`），險種是方案的險種加上加購的，寫入 `conversation_insurance`。回答時才用 RAG 在這些險種的條文裡找資訊（[ADR-0005](0005-embedding-1024-and-retrieval.md)），數字規則仍照 [ADR-0004](0004-llm-never-produces-numbers.md)。
- 理賠待辦清單（[ADR-0011](0011-claim-flow-bounded-llm-judgement.md)）同樣綁在這個對話上建立的 `claim_case`。

## 比對方式（補充）

比對看保單「承保內容」表印的**險種代碼**（`T068`、`TA46` 這類），不看後面附的條款原文：附的條款裡會出現別的代碼與商品全名，整份文字比對會多抓。資料庫的險種保單代碼（`insurance.policy_codes`，起初是 `config/policy_codes.json`，見 [ADR-0016](0016-admin-writable-backoffice-and-plan-owned-insurances.md)）把每個代碼對到條款庫的險種與章；方案含的代碼全都在表上才算比對到，有多個方案符合時取代碼最多的，表上多出來的代碼就是加購。

這是因為富邦的基礎型與進階型用同一份條款、含的險種代碼也一樣，只差「安心個人旅行綜合保險-甲型」的幾章（居家火災、居家竊盜、信用卡盜用、信用卡購物）；依險種比對會永遠判成基礎型。目前只有富邦的代碼對照；表上沒有認得的代碼（其他公司的保單）時，退回用商品全名完全比對。保額與保險期間由同一組程式規則從保單讀出，其餘金額（各項保障的保額、自負額）不存，由方案給付與保額計算。

取代 [ADR-0010](0010-policy-only-answers.md) 與 [ADR-0009](0009-policy-document-personal-data.md) 中保單段落的部分：**不再把保單內容存進資料庫**，所以沒有保單段落、保單向量，保單上傳也不做去識別化。原檔、原文、原檔名都不保存、不寫進 log。

## Considered Options

- **照 ADR-0010，保單段落與條款庫條文一起檢索**：能回答保單上寫的個人內容（被保險人、實際保額），但要存保單原文的去識別化版本與向量，個資風險與維護成本都高。
- **險種有任何一個比對到就收**：容易收進只買了方案一部分的保單，之後問答的範圍與使用者實際的契約不符。
- **用保障項目名稱比對**：名稱在保單與方案之間寫法不同（「個人責任保險」對「個人責任保障(自負額2500)」），要維護別名表；保單上的代碼是現成的穩定鍵。
- **方案的險種全部比對到才收**（採用）：寧可拒絕，也不用不完整的比對結果回答。

## Consequences

- 保單上寫的被保險人、受益人等個人資料查不到；保額與保險期間會存。需要時再另外決定。
- 沒收錄的方案、或承保內容表沒有認得的代碼的保單，會被拒絕。目前只有富邦的代碼對照，其他公司要等拿到保單樣本再補。
- 方案目前是設定檔（`config/plans.json`，九個可選方案與一個保單專用方案，見 [ADR-0026](0026-upload-only-plans-for-official-site-products.md)），日後換成別組的資料來源，只要改 `app/domain/plans.py`。
- 去識別化模組（`app/policy/deidentify.py`）與 [ADR-0009](0009-policy-document-personal-data.md) 的規則保留，給理賠文件（流程圖的 6）與 `extra_notes` 使用，保單上傳不再呼叫它。
