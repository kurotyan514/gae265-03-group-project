# 上傳保單後只依保單回答；保單明確載明的險種才拉進條款庫的條文

使用者上傳保單後的問答，只檢索該使用者那份保單的保單段落；保單沒寫的事回「保單未載明，請向保險公司確認」。例外只有一個：保單文字**明確載明**險種代碼（`T\d{3}`、`TA\d{2}`）或險種全名，且與條款庫**完全比對**到時，才把該險種的條文併入檢索，出處分開標示「保單」與「條款」。比對由程式做，LLM 不參與，也不做模糊比對。比對不到、保單沒載明、或險種不在條款庫，就只用保單段落。

理由是保單才是使用者實際買的契約：用同公司或相近商品的條款去補答案，等於替保險公司解釋條款（[ADR-0004](0004-llm-never-produces-numbers.md) 規則 5 的精神）。保單自己指名險種時，那些條款就是保單的一部分，所以例外成立。使用者上傳的保險公司也可能完全不在條款庫。

- 檢索函式內部強制帶 `user_id` 與 `policy_id` 過濾，呼叫端不可能漏帶；兩個使用者互相檢索必須查不到對方的段落（必過的測試）。
- 比對結果記在 `policy`，使用者看得到「這份保單對到了哪些險種」。
- 沒上傳保單、改選保單那條路，才直接用條款庫的條文（v1 選固定測試方案裡的險種）。
- 回答裡的數字沿用 [ADR-0004](0004-llm-never-produces-numbers.md)：LLM 的文字必須通過數字白名單，失敗就退回只顯示原文與頁碼。因此 v1 **不串流**回答，通過檢查才一次顯示。

## Considered Options

- **依公司或商品名自動套用條款庫的條款**：能答更多問題，但保單內容可能和條款庫的版本不同，會給出與使用者契約不符的答案。
- **模糊比對險種名稱**：容易把相近的險種當成同一個。
- **只依保單，明確載明才例外**（採用）：答案範圍較窄，但每一句都對得到使用者自己的文件。

## Consequences

- 只有保障摘要的保單，很多問題會回「保單未載明」；實際效果要等真實保單樣本再調整（目前以條款 PDF 當替身）。
- 保單段落暫定兩種切法：切得出足夠的「第N條」就沿用條款的切法，否則依頁、再依段落切；`policy.chunk_strategy` 記錄用了哪一種。
