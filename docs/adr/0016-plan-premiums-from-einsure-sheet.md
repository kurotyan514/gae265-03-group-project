# 方案保費與保障改用易安網試算表，查不到就不顯示

九個方案（[ADR-0014](0014-clause-bundles-and-nine-plans.md)）的保費與各保額下的保障額度，來源是組員整理的試算表 `backend/data/source/日本旅遊保險_保費保障矩陣.xlsx`（易安網實際試算）。試算表轉成資料表 `plan_premium` 與 `plan_benefit`，由 seed 匯入；後端不再用費率表推算保費。數字由程式與資料決定，不由 LLM 產生（[ADR-0004](0004-llm-never-produces-numbers.md)）。

## 決定

- **資料來源與擷取條件**：易安網旅平險頁面（https://www.einsure.com.tw/product/travel），日本、自己保（線上）、1 位旅客，2026-11-01 10:50–10:58（Asia/Taipei）擷取。起日 2026-11-01 12:00，迄日為起日加完整天數（每一天為完整 24 小時，例如 4 天為 11/1 12:00 至 11/5 12:00）。原頁預設到 11/4 12:00 僅 72 小時，本表不採用。
- **保費是來源的原始報價，不是推算**：試算表每一格都是網頁實際報價（新臺幣整數元），不用公式、不內插、不依天數或保額換算。
- **查不到就不顯示**：保額或天數不在表上（例如 3 天、身故 250 萬），或該方案在該保額沒有報價，一律視為沒有報價；API 不回傳、畫面不顯示。報價與保障明細成對：有報價就有保障明細，反之亦然。
- **不再使用 `backend/data/rates/`**：那是原型留下的富邦／國泰費率，與現在的九個方案對不上。`app/domain/pricing`、`app/domain/recommend` 與費率檔隨後移除。
- **試算表的提醒要保留在 API 文件與畫面**：保費是來源原始報價；未列保障不等於法律上無保障；定額金額不是保證的理賠最高金額或觸發門檻，實際理賠依保單條款與個案認定；正式投保仍依年齡、資格、行程、核保結果與條款辦理。
- **方案代碼**用 `plans.json` 的 `id`，不另建 `plan` 表；金額與保額一律存整數元。

## 已知限制

- 報價只有日本；選其他目的地也只能用日本的保費。
- 沒有年齡維度，保費不隨年齡變。
- 天數只有 4–10 天、身故保額只有 200–1,000 萬（各方案可投保的保額不同），超出就沒有報價。
- 沒有給付單位與上限（「每 4 小時」「最高 1.2 萬」），只能顯示試算表上的額度；累進式的單位時數與上限要從條款人工整理。

## Considered Options

- **沿用 `data/rates/` 的費率表推算**：可以任意天數、任意保額，但費率是富邦與國泰的，與九個方案對不上，推算結果也和網頁實際報價不同。不採用。
- **依年齡與目的地建完整費率模型**：這份資料沒有年齡與其他目的地，硬做只能靠推估，違反「數字不能是推估」。等有第二份資料再加。
- **缺少的保額或天數用內插補上**：畫面較完整，但會顯示不存在的報價。改為查不到就不顯示。
- **每次換版手動改資料庫**：改用轉換腳本把試算表轉成 `plan_data.json`，commit diff 看得出哪些數字變了。

## Consequences

- 換試算表時重跑 `make plan-data` 產生 seed、再 `make seed`；保額與天數的下拉選項由資料決定，前端不用改。
- 資料只有一個擷取日（2026-11-01），報價可能過期；換版時要同時更新擷取條件與本 ADR。
- 推薦與畫面只能顯示表上的保額與天數，也沒有給付單位與上限可顯示。
- 推薦規則（[ADR-0017](0017-recommendation-rule.md)）的在意事項額度由 `plan_benefit` 加總而來。
