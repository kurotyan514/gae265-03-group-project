# 送件信填完才能寄出；草稿由使用者選擇建立；寄出、建草稿、自己處理都結案

修改 [ADR-0020](0020-google-login-and-incremental-authorization.md)「授權」中送件那段的時機：按「好險有你小助理幫我送出」後，Gmail 授權不再是看信件預覽的前提，改成寄出的前提。

7 號產生的送件信一定有平台沒有的資料：被保險人姓名、保單號碼、聯絡電話。抓不到的資料一律寫成「（請填寫＋項目）」（例如「（請填寫保單號碼）」），不猜、不用 LLM 補（[ADR-0004](0004-llm-never-produces-numbers.md)）。原本的規則是「信裡有空格，7 號就存成 Gmail 草稿；沒有空格才直接寄出」。照這個規則，每一封信都會變成草稿，使用者還得到 Gmail 補完再自己寄，「好險有你小助理幫我送出」等於沒有幫忙寄。我們決定讓使用者在 App 裡填完，有空格就不能寄出；草稿只在使用者選擇自己處理時才建立，而且由使用者決定要不要建立。

**送件流程**
- 選了要送件的事件後，先問「要由我們用你的 Gmail 幫你寄給保險公司嗎？」，兩個選項：「我自己處理就好」、「好險有你小助理幫我送出」。
- **好險有你小助理幫我送出**：先顯示 Gmail 授權的用途說明（Drive 失效時先說明 Drive），不論同意或按先不要都進到信件預覽。預覽把每個「（請填寫＋項目）」換成輸入框，同一個項目只填一次；寄件者是使用者自己的 Gmail，收件者由使用者輸入。空格全部填完、收件者也填好，才能寄出；寄出時還沒有授權就再說明一次。寄出後結案。這條路不建立草稿。
- **我自己處理就好**：問「需要幫你在 Gmail 建立草稿嗎？」，並先告知不論選哪一個都會結案。選確定就說明 Gmail 授權、建立草稿後結案（授權時按先不要就回到這個問題，還沒結案）；選取消就不建立草稿，直接結案。

**填好的值怎麼送到寄信的地方**
- 前端只把「項目 → 使用者填的值」送給平台，不送整封信。平台用 7 號重新產生送件信，把值換進「（請填寫＋項目）」，再交給 7 號。只換空格這一段，使用者改不到程式產生的保額、日期等文字（ADR-0004）。
- 「（請填寫＋項目）」是 7 號、平台與前端共用的固定寫法：括號裡的文字就是項目名稱，三方都用它找空格與換值。
- 7 號寄出時，信裡還有任何「（請填寫＋項目）」就不寄，回 `failed`；這是前端與平台之外的最後一道防線。

**結案**
- 寄出（`sent`）、建立草稿（`drafted`）、自己處理不建草稿（`self_submitted`）三種都結案；寄出或建立草稿失敗（`failed`）不結案，使用者可以處理後再試。
- 結案後不能再新增狀況或修改，也不能再送件，避免寄出重複的信。

## Considered Options

- **有空格就存成草稿，沒空格才直接寄出**（原本的規則）：7 號自己就能決定寄出或建草稿，契約只要加 `drafted`。但被保險人姓名、保單號碼、聯絡電話一定是空格，結果一律存草稿，代寄的選項形同虛設。沒採用。
- **有空格也照樣寄出，讓保險公司再來問**：使用者最省事，但保險公司收到「（請填寫保單號碼）」這種信，只會退件或來回補件，反而更慢。沒採用。
- **前端把使用者改好的整封信送給平台**：前端最簡單，但使用者就能改到保額與日期，平台也得信任前端送來的內容，違反 ADR-0004。改成只送「空格 → 值」。
- **在契約加一個欄位列出缺的項目，不靠固定寫法**：比較正式，但信件內文本來就要寫出「（請填寫＋項目）」給使用者看，再另外列一次就有兩份資料可能對不上。採用固定寫法，並由 7 號的測試守住。
- **建立草稿後不結案，等使用者真的寄出才結案**：比較接近事實，但系統不追蹤使用者 Gmail 裡的草稿與寄件（ADR-0020 不請求 readonly 權限），永遠不會知道使用者寄了沒有，事件會一直停在未結案。改成選擇時就先告知會結案。

## Consequences

- 契約要改（v2.1）：`send` 要能分辨寄出或建立草稿，`SendResult` 加 `drafted`。
- 平台的送件 API 要收「寄出／建立草稿／自己處理」與「空格 → 值」；資料表 `policy_submission` 的 `drafted` 說明從「不結案」改成結案，`recipient` 在建立草稿時可以沒有值。
- 平台要在結案後擋下所有會修改事件的 API；目前完全沒有這個檢查。
- 送件信只要還有一格平台沒有的資料，正式網站就寄不出去，直到平台的送件 API 能帶使用者填的值。
- 結案要鎖單一事件還是整張保單，等以保單為單位的送件（`build_for_policy`）一起決定；送件紀錄目前是以保單為單位，送件 API 是以事件為單位。
- 平台要改的地方整理在 [docs/agents/handoff/platform-agent-7-send.md](../agents/handoff/platform-agent-7-send.md)，7 號的規則在 [docs/specs/agent-7-package.md](../specs/agent-7-package.md)。
