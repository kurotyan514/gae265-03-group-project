# 不再有「保險公司」這個資料：公司名寫在方案名稱裡

資料庫不存保險公司：`insurance` 沒有 `company` 欄位，後台上傳條款也不再問公司。不同公司的方案直接用方案名稱區分，例如「富邦旅平險…」。

## 影響

- **資料庫**：migration `drop_insurance_company` 刪掉 `insurance.company`；seed 檔不再匯出、匯入這個欄位（舊 seed 檔裡多的 `company` 會被忽略）。
- **上傳條款**：`POST /ingest/jobs` 與 `/dev/ingest` 拿掉 `company`。原本用公司名辨識「商品標題行」，現在固定用第一行當標題，所以標題行不再需要公司名。
- **寬鬆條號規則**：原本靠公司名單（中信）決定要不要把「第一條承保範圍」這種條號與標題黏在一起的寫法切開；現在先用嚴格規則切，寬鬆規則切出的條文比較多時才改用它，並記進修復動作。
- **不受影響**：合訂本設定檔（`config/` 的 bundles）裡的 `company` 仍是解析用的標題行開頭；`policy/matching.py` 比對使用者保單名稱時去掉公司前綴；方案資料（`plans`）與保費表本來就有公司名，不在這次範圍。

## Considered Options

- **上傳時勾選「條號與標題黏在一起」**：行為明確，但上傳的人要知道該勾。沒採用，因為自動偵測只會多切、不會少切（寬鬆規則只收條號剛好接續的行）。
- **保留 `company` 但改成選填**：資料庫和 API 仍有一個沒人維護的欄位，之後的人會誤以為它可靠。沒採用。
